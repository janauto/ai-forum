# AI 研发工作空间（员工端）· 原型需求文档 v1.0

> [!quote] 一句话定位
> **一个以「项目」为入口的 AI 工作空间：把项目管理、对话助手、工具调用融在同一个窗口里。工作在这里发生，产出自动沉淀到云端并被结构化——省掉中间人反复汇总的环节，让研发产出可复用、可追溯、可流通。**

> [!note] 这份文档是什么
> 它把你口述的产品构想结构化为可评审、可落地的需求，并回答三个关键问题：**我们要画哪些界面、每个能力背后的数据/记忆怎么流动、AI 在每个环节是"给事实"还是"下判断"**。本文末尾附一份可点击的低保真原型。

---

## 0. 一页读懂

**它本质上是一个"AI Coding IDE 形态的工作助手"。** 你打开一个项目窗口，像和 IDE 对话一样和它聊：问项目问题、让它调工具、让它生成产出。本地有一个独立项目文件夹与之同步，同时对接钉钉的项目文件夹与项目管理。工作完成，产出自动提交云端并被结构化记录。

三大模块 + 一组贯穿能力：

| 模块 | 一句话 | 对应你的口述 |
|---|---|---|
| **① 工作台** | 以项目为入口，按优先级排布；进入项目即对话；基于历史弹 2-3 条待办 | 「第 1 点」 |
| **② 创作** | 前沿 AI / 建模 / 画图工具，按岗位推荐，可一键插入当前项目 | 「第 2 点」 |
| **③ 案例库** | 已解决的技术难题与项目经验，部门资产，透明可迭代 | 「第 3 点」 |
| **④ AI 会议** | **可单人发起、无需约时间**；会前 AI 生成问答脉络，会后把口头阐述拆成"可解决/需协助/风险"，经 FDE 审理后透传分发并留痕 | 「本次新增」 |
| **贯穿能力** | 记忆与文本压缩 · 后台风险/任务自动分配 · 工作信息→绩效与数字资产 · 钉钉/本地/云端同步 | 「总特性 1/2/3」 |

> [!important] 本期原型只验证一个核心假设（信条 15）
> **"研发愿意把工作搬进这个空间——因为它真的省事（待办接着做、工具一键调、产出自动沉淀），而不是多一道填报负担。"**
> 自动绩效、跨部门 Agent 协同、全面钉钉双向同步等，标记为「以后再说」。

## 1. 与《理念册子》的对齐与张力（必读：这是设计否决线）

你的新构想比册子里的"只记录、不判断"更进了一步——它要**自动评估产出、自动给解决方案、自动算绩效、自动推送风险**。这几处恰好踩在信条 5/6（"AI 当见证者不当裁判""辅助为主，自动化是陷阱"）的边界上。这不是要否定新构想，而是要**有意识地处理**，否则团队会抵触、AI 会被边缘化。

| 新构想里的能力 | 触碰的信条 | 处理方式（改良红线） |
|---|---|---|
| 产出"自动评估" | 信条 5/6：评估=判断 | **不打分裁决**。评估只做两件事：① 客观计量（产出了什么、对应哪些里程碑、字数/文件/提交）；② 事实对比（"同类产出历史平均 X"）。需要结论时进**待确认队列**，由负责人确认 |
| 卡点"自动给解决方案" | 信条 5：AI 不当裁判 | 方案一律标注为**"检索到的参考"+ 来源**（案例库/历史项目/外部），不写"建议你用"。人来选 |
| 风险"自动推送 PM" | 信条 5：陈述 vs 判断 | 推送的是**事实**："卡点『接收延迟』已持续 3 天、超过同类均值 X"，不是"高风险" |
| 工作信息→"绩效指标" | 信条 14：阻力 / 隐私 | **客观计量，员工自己可见自己的数据**；定位为"数字资产贡献"而非监控。绝不让 AI 给人打分 |
| 产出"自动提交云端" | （不违背）信条 1/2 | ✅ 这是"在第一时间结构化记录"，属于见证者动作，鼓励 |

> [!warning] 三条改良红线（贯穿全产品）
> ① 自动化只做「记录 / 归档 / 检索 / 呈现 / 触发提醒」，**判断与签字永远留给人**；
> ② 任何"评估/打分"要么改为**客观计量 + 历史事实对比**，要么进**待确认队列**由人确认；
> ③ AI 给的"解决方案"一律标注**"参考 · 来源 X"**，末尾保留「由 [负责人] 确认」。

这样既实现你要的"省掉中间人、快速响应"，又不滑向"不可信、无人负责"的自动决策陷阱。

## 3. 模块详述

### 3.1 工作台（Workspace）—— 核心入口

**布局：左侧项目列表 · 中间项目对话窗 · 右侧项目记忆/产出面板。**

#### A. 项目入口与优先级排布
- 左侧按**优先级 + 紧迫度**自动排序的项目卡，每张卡显示：
  - 项目名（例：`蓝牙连接功能`）
  - `进行时间 5 天` · `预估剩余 2 天` · `项目阶段：联调`
  - 进度环 / 紧迫度标识（用事实驱动：剩余时间、里程碑达成率；不用"高/低风险"主观标签）
- 一个常驻的 **`自由探索`** 项目（默认项目），承接"不属于具体项目"的探索与日常。
- `+ 新建项目`：可绑定本地文件夹路径 + 钉钉项目。

#### B. 项目对话窗（IDE 式）
- 进入项目即进入对话。可问项目问题、让它调工具、生成产出。
- 上下文来自**项目记忆**（见 6.1）：历史对话被压缩进项目状态，所以它"记得"这个项目之前发生过什么。
- 输入框上方有**快速插入**：`MVP 电路图` / `3D 模型` / `时序图` / `会议前置文档` / `代码` / `文档`（按角色变化，连通"创作"模块）。

#### C. 待办弹出（2-3 条，基于项目历史主动推送）
进入项目时，系统读项目历史与日程，弹 2-3 条"可以接着做"的卡片，点一下就继续。**示例（原型内置）：**

> [!example] 嵌入式软件工程师
> - **自由探索**：①「最新 4G 模块前沿速览」 ②「怎么用 AI 开发嵌入式」 ③「下午 5 点与产品部会议——是否直接生成会议前置文档？」
> - **蓝牙项目**：「蓝牙项目快截止了，当前卡点是『接收延迟』。已为你找到 3 个参考方案，看看是否有用 →」

> [!example] 产品经理
> - 「下午的方案商会议——是否生成会议前置文档？」
> - 「当前 XX 方案可能存在延期风险（卡点已 N 天），这里有几条参考解决思路」
> - 「快充氮化镓架构的方案商还未确定——是否进入筛选评估？」
> - 「协议芯片屏幕开发，已收集到 N 家方案商，是否足够开始评估？」

> 每条待办都遵守改良红线：给的是**事实 + 参考**，动作是**让你接着做**，不替你决定。

#### D. 产出与同步
- 对话/创作产生的产出（文档、电路图、代码、评估表）落入**项目文件夹**：本地副本 ↔ 云端 ↔ 钉钉，三方同步。
- 完成后**自动提交云端并结构化记录**（产出物 + 关联里程碑 + 知识所有人 + 时间），进入"评估/计量"——按 §1 红线，只做客观计量与事实对比。

### 3.2 创作（Creation）—— 探索版，共建

- **能力画廊**：前沿 AI、建模、画图等工具/模型，**按岗位推荐**：
  - 嵌入式：MVP 电路图生成、时序图、状态机、代码脚手架、数据手册速读
  - 产品经理：会议前置文档、方案商对比表、PRD 生成、竞品速览
  - 通用前沿：3D 建模、流程/架构图、最新模型尝鲜
- **一键插入项目对话**：例如项目来了"快充技术研发"，一键生成 MVP 电路图回填到对话；建模需求则生成 3D 图片。
- **共建机制**：标注「探索版 · 共建」，提供「贡献一个能力」入口——大家一起维护这个能力库（呼应"数字资产"）。

### 3.3 案例库（Case Library）—— 部门资产，透明

- 收录**已解决的技术难题**与**项目经验**，作为可持续迭代的部门资产、透明信息库。
- 每条案例字段（呼应信条 2/3/4，并复用 [[2026_06_AI研发中台_原型需求文档_v1]] 的两段式）：
  - `标题` · `场景 / 结果 / 原因`（轻量三字段，成功失败平等收录）
  - `约束条件`（复用前必填，信条 3）· `知识所有人`（信条 16）· `关联项目` · `复用次数`
- 检索结果分三区呈现：**已验证 / 预研 / 未知**（信条 11，未知区敢说"这是空白"）。
- 案例可被对话直接引用、被创作能力消费，形成"用得越多越值钱"的资产飞轮。

### 3.4 AI 会议（Meeting）—— 会前生成脉络、会后结构化拆解与透传

从项目内点击「发起 AI 会议」，打开一个语音对话，把一次会议从"口头表达"变成"结构化、可分发、可留痕"的资产。**这是切信息失真最猛的一个节点（信条 1）——会议是失真重灾区。**

> [!tip] 产品特色：会议可以一个人开
> AI 会议默认是**单人会议**——你不必预约他人时间、不必凑日程，自己坐下来把问题对着 AI 讲清楚即可。AI 当对手方帮你澄清、拆解、初判；结论与待办在会后**异步透传**给干系人，他们无需到场。这把"开会"从一件需要同步协调的事，变成一件随时能做、**零排期成本**的事——与本产品"省掉中间人、信息不失真"的内核一致。（多人实时会议作为可选模式保留。）
>
> 所以这里的"参与人"本质是**干系人 / 分发对象**，不是必须到场的与会者。

**流程（5 步，原型可逐步点击演示）：**

1. **会议设置**：填写会议主题、大概内容/议题、关联项目、干系人。
2. **AI 主持会议（对话式）**：AI 据内容把控一份"问答脉络"作为**幕后提纲**，然后**像真人主持一样和你一问一答**——根据你的每个回答临场追问、澄清、转场，全程语音。**不是甩给你一份文档让你对着逐条作答**——脉络只是 AI 的提纲，会议本身是交流。
3. **AI 拆解**：把对话内容拆成三类——`可自行解决` / `需外部协助` / `风险点`，并对优先级做**初步规则判断**（例：进行中项目的阻塞性卡点 > 新预研）。标注"初判 · 待 FDE 审理"。
4. **FDE 工程师审理（人确认门）**：AI 只做初判，**必须经 FDE 工程师审理（人确认、人担责）才放行**——这正是信条 6 的落地，把"自动化"挡在判断之外。
5. **透传分发 & 留痕**：审理通过后按对象**透传分发**（可解决项进本人待办、协助请求通知对应同事、优先级/风险点告知干系人），无需中间人二次汇总；需求评审事项记入**会议留痕**，作为后续会议的前置参考（信条 16 可追溯）。

> [!example] 你给的场景（已内置到原型·嵌入式视角）
> "蓝牙接收做完了但延迟 80ms 偏高、可能影响整机，同时下周要启动 4G 模块预研，优先级怎么排？" → AI 拆解为：可自行解决（增大缓冲/关日志，参考案例 #A-203）、需外部协助（射频确认天线、PM 确认 4G 窗口）、风险点（延迟超标、并行人力冲突），并初判"先收敛蓝牙、4G 顺延"，提交 FDE 审理 → 通过后透传给各干系人。

> [!warning] 红线
> AI 在会议里的角色是**记录 + 结构化拆解 + 初步规则初判**；**优先级与风险的最终结论由 FDE 工程师审理签字**。严禁 AI 直接对人、对优先级下最终判断（信条 5/6）。

## 4. 贯穿能力（总特性）

### 4.1 记忆与文本压缩（总特性 1）
- **以项目为记忆对象**：每个项目维护一个结构化"项目状态"（目标、阶段、关键决策、卡点及其时长、产出清单、参与人）。
- **自动压缩**：长对话被周期性摘要并合并进项目状态，旧消息折叠，**上下文始终轻量且最新**。
- **快速更新 + 后台触发**：状态更新即写入；满足触发规则时推后台（见 4.2）。
- 决策/预测**append-only 存档**（信条 8/16），可追溯、可对比。

### 4.2 后台风险 / 任务自动分配（总特性 1 续）
- 规则示例：`某卡点持续时长 > 阈值（如同类均值或 3 天）` → 在后台**向项目经理推送事实**（"卡点 X 已持续 N 天"）+ 附**检索到的参考方案及来源**，让各部门快速灵活响应。
- 严格按 §1：推事实不推判断，给参考不替决定。

### 4.3 工作信息 → 绩效与数字资产（总特性 2）
- 采集**客观计量**（产出记录、卡点响应时长、案例贡献数、复用被引数），作为"合理绩效"的事实输入与公司数字资产。
- 员工**可见自己的数据**；定位为贡献度与透明流通的指导，而非 AI 打分、非监控。

### 4.4 同步与集成（钉钉 / 本地 / 云端）
- **本地**：独立项目文件夹，离线可用，作为工作现场。
- **钉钉**：双向对接钉钉项目文件夹与项目管理（任务、日程→驱动待办弹出与会议前置文档）。
- **云端**：产出自动提交、结构化沉淀、团队可见。
- 三方同步策略、冲突处理为后续工程细化项（见 §7 待确认）。

## 5. AI Coding 平台 & Hermes 记忆层 · 可行性评估

> 你提到"Coding 平台想用 Hermes 的记忆部分进行改版"。先说结论，再说做法。

**先澄清歧义**："Hermes" 指向不唯一，可能是：(a) Nous Research 的 Hermes 系列模型；(b) 某 Agent/Coding 框架的记忆模块；(c) 你们内部代号。**请在评审时确认具体所指**（见 §7）。但无论指哪个，下面的结论都成立：

**结论：记忆"做法"可借鉴，但建议自建/私有化记忆层，不绑定单一框架。** 理由：
1. 你的目标是"公司数字资源资产化 + 产出透明" → 记忆与产出数据必须**自有、可私有化部署、可追溯**，不能锁死在第三方框架的存储里。
2. 大多数 Agent 栈的"记忆部分"本质是一组**可移植的设计模式**（摘要压缩 + 向量检索 + 结构化状态 + 事件日志），采纳模式即可，不必采纳整个框架。

**建议的记忆层架构（与信条 8/16 对齐）：**

| 层 | 作用 | 关键设计 |
|---|---|---|
| 项目状态库（结构化） | 存项目"当前真相"：目标/阶段/卡点/产出 | 可读可改，改动留 diff + 人 + 时间 |
| 对话摘要 / 压缩 | 长对话→要点，喂给上下文 | 周期压缩，原文归档不删（信条 16） |
| 向量检索 | 把案例库/历史项目召回到对话 | 召回结果落三区（信条 11） |
| 事件 / 决策日志 | AI 预测、人的决策、产出提交 | **append-only 不可改**（信条 8） |
| 触发引擎 | 卡点时长等规则→后台推送 | 推事实不推判断（§1 红线） |

**风险与边界：** 数据驻留与合规（数字资产须私有可控）、框架锁定、与钉钉/本地三方同步的一致性。建议 MVP 阶段记忆层**自研一个最小版**（项目状态库 + 对话压缩 + 案例向量检索），把 Hermes 当"参考实现"而非"直接依赖"。

## 6. 原型页面清单（本文件附带的可点击原型覆盖项）

1. **工作台**：项目列表（优先级卡）+ 自由探索 + 项目对话窗 + 2-3 待办弹出 + 快速插入 + 右侧项目记忆/产出面板
2. **创作**：按岗位推荐的能力画廊 + 一键插入 + 共建入口
3. **案例库**：搜索/筛选 + 三区案例卡（含约束/所有人/复用数）
