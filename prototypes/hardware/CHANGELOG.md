## ✨ 新增功能

### 1. **真实芯片组件系统**

#### 新增 4 种可交互芯片组件（library.js）
- **chip_mcu**：主控芯片（AW313A/IP5328/IP5389 可选）
  - 显示型号、运行状态（●/○）、封装信息
  - 支持开关机、过热告警事件
  
- **chip_pd**：PD协商芯片（HUSB238）
  - 实时显示协商电压（5V/9V/12V/20V）
  - 可触发电压协商，协商成功边框变紫色
  
- **chip_gauge**：电量计芯片（CW2015）
  - 显示 SOC 百分比 + 电池电压（mV）
  - 低电量自动变红告警
  
- **chip_sensor**：通用传感器芯片
  - 可配置型号、接口类型（I2C/SPI）
  - 实时显示传感器数值

#### 芯片视觉效果（styles.css）
- 深色渐变背景 + 左右引脚装饰纹理
- 悬停青色光晕 + 状态脉冲动画
- 数值高亮发光效果
- 响应式尺寸（大芯片 160×120px，小芯片 140×100px）

---

### 2. **产品架构方案库（architecture.js）**

#### 内置 2 个真实充电宝硬件方案

**基础款 10000mAh**
- 主控：AW313A（JIELI BLE SOC）
- PD芯片：HUSB238（需外挂）
- 电量计：CW2015（I2C）
- 电池：18650 × 2（1S2P）
- 传感器：NTC 10K（ADC）

**旗舰款 20000mAh**
- 主控：IP5389（集成PD+电量计）
- 显示：SSD1306 OLED（128×32）
- 电池：21700 × 3（1S3P）
- 双温度监控（电池+主控）

#### 每个方案包含
```javascript
{
  bom: [],              // 器件清单（型号+角色+厂商）
  topology: {
    nodes: [],          // 芯片节点（带坐标和类型）
    edges: []           // 连接关系（协议标注：I2C/ADC/PD）
  },
  signal_flows: []      // 场景化信号流（充电/放电/保护）
}
```

### 3. **芯片数据库增强（chipdb.js）**

#### 从底层寄存器转向架构层描述

**新增架构层信息**：
- `interfaces`：芯片接口类型（power_in/battery/display/sensors）
- `typical_peripherals`：典型外围芯片组合
- `functional_blocks`：功能模块特性（不涉及寄存器）

**删除/简化**：
- ~~寄存器地址（P3_CHG_CON0）~~
- ~~具体 API 调用（gpio_write）~~
- ~~精确引脚编号（IO_PORTA_02）~~

**保留核心**：
- 真实芯片型号（AW313A, HUSB238, CW2015）
- 通信协议（I2C, ADC, USB PD）
- 功能特性（充电管理、电量计算、协议识别）

---

### 4. **增强代码生成器（codegen_enhanced.js）**

#### 智能引脚分配
- 根据芯片推荐引脚自动分配
- 避免功能引脚（BLE/USB）冲突
- 优先分配：LED→PA2/PA3，Button→PA5/PA6，ADC→PA1

#### 引脚冲突检测
- 自动检测多设备占用同一引脚
- 生成冲突报告和警告信息

#### 内存预算估算
- 计算系统栈/用户栈/BT RAM/应用数据
- 显示总量、使用率、是否超限
- AW313A 总 RAM 限制：7KB

#### 生成完整项目结构
```
project/
├── board_config.h    # 引脚宏定义
├── app_config.h      # 内存/BLE/定时器配置
└── app_main.c        # 主程序（设备初始化+电源管理）
```

---

### 5. **PRD 解析器升级（prd.js）**

#### 集成增强代码生成器
- 优先使用 `CodeGenEnhanced` 生成真实项目
- 输出引脚分配表、内存报告、冲突警告
- 多文件输出（用分隔符区分）

#### 后备方案保留
- 原有代码生成逻辑作为 fallback
- 确保兼容性

## 🔧 改进优化

### 架构调整

**核心理念转变**：
- **优化前**：生成可编译的寄存器级代码（绑定具体 SDK）
- **优化后**：生成架构级骨架（芯片方案 + 通信协议，可移植）

**原因**：
1. 用户反馈"不需要太涉及硬件底层"
2. 芯片可能变动，但逻辑保持一致
3. 架构拓扑更适合产品选型和评审

### 代码质量

- **总代码量**：3629 行
  - app.js: 832 行（主控制器）
  - library.js: 552 行（18种组件）
  - styles.css: 520 行（视觉样式）
  - codegen_enhanced.js: 430 行（代码生成）
  - chipdb.js: 409 行（芯片数据库）
  - prd.js: 377 行（PRD解析）
  - architecture.js: 193 行（方案库）
  - engine.js: 156 行（联动引擎）

- **模块化设计**：每个 JS 文件职责单一
- **无外部依赖**：纯原生 JavaScript + CSS3

## 🎯 核心价值

### 对比优化前后

| 维度 | v0.x（抽象层） | v1.0（架构层） |
|------|---------------|---------------|
| **设备** | 按键、LED、传感器 | + 真实芯片（AW313A, HUSB238） |
| **拓扑** | 简单箭头 | 芯片级连接 + 协议标注（I2C/ADC） |
| **BOM** | 无 | ✅ 完整器件清单 |
| **方案** | 单一抽象 | ✅ 可选基础款/旗舰款 |
| **代码** | 绑定寄存器 | ✅ 架构骨架（可移植） |
| **交互** | 按键/LED | ✅ 芯片可操作（协商电压/更新SOC） |

### 适用场景

**v1.0 适合**：
- ✅ 产品需求 → 硬件架构方案
- ✅ 芯片选型与对比
- ✅ BOM 清单生成
- ✅ 信号流可视化
- ✅ 架构级代码生成

**不适合**：
- ❌ 寄存器级调试
- ❌ 驱动程序开发
- ❌ 实时固件仿真

## 🐛 已知问题

### 限制
1. **拓扑图未可视化**：`architecture.js` 中的拓扑数据暂未渲染到界面
2. **芯片联动规则较少**：需补充更多芯片间的典型联动场景
