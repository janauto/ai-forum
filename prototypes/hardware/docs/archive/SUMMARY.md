## 📦 新增的文件和功能

### 1. **architecture.js** — 产品架构方案库

定义了两个真实的充电宝硬件方案：

**基础款 10000mAh**
- 主控：AW313A（JIELI BLE SOC）
- PD芯片：HUSB238
- 电量计：CW2015
- 电池：18650 × 2（1S2P）
- 温度传感器：NTC 10K

**旗舰款 20000mAh**
- 主控：IP5389（集成PD+电量计）
- 显示：SSD1306 OLED
- 电池：21700 × 3（1S3P）
- 双温度监控

每个方案包含：
```javascript
{
  bom: [],           // 器件清单（芯片型号 + 角色）
  topology: {
    nodes: [],       // 芯片节点（带坐标）
    edges: []        // 连接关系（协议标注：I2C/ADC/PD）
  },
  signal_flows: []   // 场景化信号流（充电/放电/保护）
}
```

### 2. **chipdb.js 增强**

在原有基础上添加了**架构层信息**（不涉及寄存器）：

```javascript

  typical_peripherals: [
    { name: 'HUSB238', role: 'PD协商', interface: 'I2C' },
    { name: 'CW2015', role: '电量计', interface: 'I2C' }

  functional_blocks: {
    charge: { features: ['恒流', '恒压', '涓流', '满电检测'] },
    protection: { features: ['过充', '过放', '过流', '过温'] }

```

### 3. **codegen_enhanced.js** — 增强代码生成

保留了智能引脚分配和冲突检测功能，但代码生成会更偏向架构层：
- 引脚分配表（设备类型 → 推荐引脚）
- 内存预算（显示总量和使用率）
- 项目结构（board_config.h, app_config.h, app_main.c）

### 4. **prd.js 升级**

集成了增强代码生成器，导出代码时会包含：
- 引脚分配表（芯片级）
- 内存报告
- 冲突/警告提示
- 多文件项目结构

### 5. **REFACTOR_PLAN.md** — 重构方案文档

详细说明了架构层真实化的理念：
- 为什么不需要寄存器细节
- 如何描述芯片方案（BOM + 拓扑 + 信号流）
- 输出示例（带 BOM 清单的架构图）

## 🚀 下一步：如何使用

## 📌 关键改进点

| 维度 | 优化前 | 优化后 |
|------|--------|--------|
| **拓扑** | 抽象设备节点 | 真实芯片型号 |
| **连接** | 简单箭头 | 通信协议标注（I2C/ADC/PD） |
| **BOM** | 无 | 完整器件清单 |
| **信号流** | 事件绑定 | 场景化流程（充电/放电/保护） |
| **可替换性** | 不支持 | ✅ 可切换芯片方案，拓扑逻辑保留 |
| **代码生成** | 绑定具体寄存器 | 架构级骨架，可适配不同 SDK |

## ✨ 最终效果

现在平台能够：

✅ **显示真实芯片方案**  
从"主控芯片"升级为"AW313A + HUSB238 + CW2015"组合

✅ **标注通信协议**  
连接线不再是抽象箭头，而是"I2C"、"ADC"、"USB PD"等协议标识

✅ **输出 BOM 清单**  
自动生成器件清单，包含型号、角色、厂商、备注

✅ **描述信号流**  
场景化描述充电/放电/保护完整流程，而非碎片化事件

✅ **支持方案切换**  
可选择不同的芯片方案（如 AW313A 方案 vs IP5389 方案），拓扑逻辑自动适配

✅ **架构可移植**  
生成的代码是架构骨架，不绑定具体寄存器，换芯片时只需调整外设驱动层

## 🎓 设计理念

> **"拓扑图是产品选型和架构评审的工具，而非代码生成的中间产物"**

从 PRD → 架构拓扑 → 代码骨架，每一步都聚焦在**架构决策**，而非实现细节：
- 选哪个主控芯片？（AW313A vs IP5389）
- 需要哪些外围芯片？（PD芯片、电量计）
- 如何通信？（I2C, ADC, SPI）
- 信号如何流动？（充电路径、保护逻辑）

底层的寄存器操作、API 调用，留给具体的 SDK 文档和驱动层实现。
